Mission and how to use this document
You are taking over a final-year university project, DiffShield, from a team of 5 students.
Your job is to implement, run and evaluate the improved version (v2) and produce the
code, results, figures and report material for it. This document is your complete brief: read
it fully before doing anything, then follow Section 6 in order.
The project in one paragraph. People post face photos online and anyone can feed them
to a diffusion-model editor (Stable Diffusion img2img, inpainting, and similar) to make
fakes. DiffShield adds an invisible adversarial perturbation to the photo (an Lâˆž-bounded
noise found by PGD) so that edits made from the protected photo no longer look like the
same person, while the protected photo looks identical to the original. v2 makes it survive
"purification" (attackers cleaning the noise off first), tests it fairly, and compares it with
existing tools.
This is a defensive, privacy-protecting project. It protects people's own photos. It does
not generate fakes of real people for any other purpose.
What done looks like:
1. A versioned repo that reproduces every number with one command per step.
2. Result tables and figures for experiments E0 to E10 (Section 7), with confidence
intervals.
3. A short threat-model-first report section and an honest list of failure cases.
4. A small demo script that protects an image and shows before and after edits.
Who decides what. The students decide scope, deadlines and anything marked "ask the
user" in Section 9. You decide implementation details. When unsure which side a choice is
on, ask.

Target system (v2)
Two halves that must never share components.
Half A, the protection loop (offline). For each photo x, repeat PGD steps:
1. Draw a purifier P from a training mixture, and transform randomness Î¾  (EoT).
2. Compute scores on P(x + Î´ ): latent shift (L_vis), denoiser error (L_den), identity loss
through ArcFace (L_id, added in Phase 6), semantic term (L_sem, kept only if the
ablation shows it helps), and a visibility penalty L_str computed on x + Î´  itself (the
published image), not on the purified one.
3. Step Î´  by sign gradient, clip to the Lâˆž ball of radius Îµ , repeat.
\delta^* = \arg\max_{\|\delta\|_\infty \le \epsilon} \; 
\mathbb{E}_{P,\xi}\big[\alpha\, L_{vis}(x, P(x+\delta;\xi)) + \eta\, L_{den}
(P(x+\delta;\xi)) - \beta\, L_{sem}(P(x+\delta;\xi))\big] - \gamma\, L_{str}
(x, x+\delta)
Half B, the attack-and-score harness. Takes a protected image, applies held-out purifiers,
edits with several editors, and scores with ArcFace identity retention and LPIPS. This is
how every claim is measured.

PGD loop with purifiers in EoT.
def protect(x, purifiers, probs, cfg, m):
    eps  = cfg.eps_255  * 2 / 255        # [-1,1] scale; 4/255 standard => 
8/255 here
    step = cfg.step_255 * 2 / 255
    z_clean = m.encode(x).detach()
    delta = (torch.rand_like(x) * 2 - 1) * eps * 0.5   # random start
    for _ in range(cfg.iters):
        delta.requires_grad_(True)
        g = torch.zeros_like(x)
        for _ in range(cfg.k_draws):
            P  = sample_purifier(purifiers, probs)
            xp = P(torch.clamp(x + delta, -1, 1))
            loss = (cfg.alpha * l_vis(m, xp, z_clean)
                    + cfg.eta * l_den(m, xp)
                    - cfg.beta * l_sem(m, xp)
                    - cfg.gamma * l_str(x, x + delta))   # visibility on the 
published image
            g += torch.autograd.grad(loss, delta)[0]
        delta = (delta + step * g.sign()).clamp(-eps, eps)
        delta = (torch.clamp(x + delta, -1, 1) - x).detach()
    return torch.clamp(x + delta, -1, 1)

def l_vis(m, xp, z_clean):               # maximize
    return F.mse_loss(m.encode(xp), z_clean)
def l_den(m, xp):                        # maximize; one UNet pass at a 
random timestep
    z = m.encode(xp)
    t = torch.randint(50, 300, (z.size(0),), device=z.device)
    n = torch.randn_like(z)
    zt = m.scheduler.add_noise(z, n, t)
    pred = m.unet(zt, t, encoder_hidden_states=m.null_cond).sample
    return F.mse_loss(pred, n)

        self.t_min, self.t_max = t_min, t_max
    def forward(self, x):
        z0 = self.vae.encode(x).latent_dist.mean * self.s
        t  = torch.randint(self.t_min, self.t_max, (x.size(0),), 
device=x.device)
        ab = self.ab[t].view(-1, 1, 1, 1)
        zt = ab.sqrt() * z0 + (1 - ab).sqrt() * torch.randn_like(z0)
        eps = self.unet(zt, t, encoder_hidden_states=self.c.expand(x.size(0), 
-1, -1)).sample
        z0h = (zt - (1 - ab).sqrt() * eps) / ab.sqrt()
        return self.vae.decode(z0h / self.s).sample.clamp(-1, 1)

Risks and how to handle them.
Compute: multi-step purifier gradients are expensive. Use the one-step purifier and
checkpointing in the loop; keep multi-step purification for evaluation only.
Robustness costs invisibility. Show the Îµ  sweep (E9) instead of hiding the trade-off.
Surrogate gap: the one-step purifier is not the attacker's purifier. Held-out tests
expose it; report it.
Adaptive attackers (LightShed-style) may still win. Randomization helps; report the
real result.
A baseline or model may not run or may be unavailable. Document it and continue.
Inpainting: if an attacker masks the face itself, the masked pixels are discarded before
the model sees them, so noise there cannot protect it. State this in the threat model.
Expected outcome. Cheap purifiers (JPEG, down-up, VAE round trip) largely fixed; partial
transfer to low-strength DiffPure; weak protection at high purification strength, against
restoration-based purifiers and against adaptive attackers. Partial but measured results
are a good outcome.
What to claim, and what not to. Claim: "Under a stated threat model (white-box SD
encoders, listed editors and purifiers, Îµ  = X/255), DiffShield lowers ArcFace identity
retention of edits by A points versus a noise control and B points over v1, including after
[held-out purifiers]; an adaptive attacker reduces this to C." Do not claim: survives any
scenario, immunity to purification, or protection against editors and attacks that were not
tested.
